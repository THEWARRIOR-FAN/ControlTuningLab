# EmbeddedWebControlExperiments

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![GitHub Pages](https://img.shields.io/badge/GitHub%20Pages-live-brightgreen)](https://thewarrior-fan.github.io/EmbeddedWebControlExperiments/)

基于网页技术的控制系统仿真实验集合：用可交互的界面直观理解不同控制模型的工作原理与参数调节方法。

**纯前端实现** —— HTML5 + CSS3 + JavaScript + Canvas，无依赖、无构建、无后端，下载即可运行。

## 在线演示

<https://thewarrior-fan.github.io/EmbeddedWebControlExperiments/>

由 GitHub Pages 在每次推送 `main` 分支后自动部署。

## 快速开始

**方式一：直接打开**

双击 `water-tuner.html` 或 `temp-tuner.html`，用任意现代浏览器打开即可。

**方式二：本地静态服务**

```bash
python -m http.server 8000
# 浏览器访问 http://localhost:8000/water-tuner.html
#           http://localhost:8000/temp-tuner.html
```

## 功能特性

两个实验共享同一套交互骨架：参数滑块 + 微调按钮、预设带预期现象说明、PID 公式卡实时代入数字、Canvas 曲线可暂停回看、1×/50×/100× 倍速与固定物理步长。

**水位调参实验（`water-tuner.html`）**

- 实时水位仿真与可视化，目标水位可调
- 核心区只放关键量：当前液位、目标、误差、实际阀位四个大字指标
- PID 公式卡：P/I/D 每项单独一行，代入当前误差、参数、水位速度的真实数值，颜色区分，末行显示限幅与延迟路径
- 进出水平衡一行提示（净进/净出/平衡），帮助理解稳态
- 次要数据（仿真时间、存水、理论静差、累计溢流）默认折叠，物理模型说明收入左侧折叠区
- 基于真实单位的体积守恒和底部小孔出流模型
- 推荐 PI 参数与 P / PI / PID 三组实验预设（不是在线自动整定）

**调温实验（`temp-tuner.html`）**

- 实时水温仿真：0–100 °C 双柱温度刻度条——橙柱为实际水温、蓝柱为测量温度（控制器所见），两柱顶差即传感器滞后；红色目标线与橙色虚线标出控制误差，加热管红热程度跟随功率
- 双曲线对比：蓝实线测量温度、橙虚线实际水温，直接看见 25 s 传感器滞后
- 加热/散热功率一行提示（净加热/净散热/热平衡），帮助理解稳态
- 六组预设覆盖 P 偏小/合适/偏大、PI 合适、I 过大、PID 微调六种现象
- 预期现象均为实测标定（静差、超调、振幅、周期），可对照曲线验证

## 当前实验：水位调参（`water-tuner.html`）

**实验目的**：理解 PID 控制器的工作原理，掌握 Kp、Ki、Kd 对系统性能的影响。

**推荐调参顺序**

1. 先了解被控对象的特性，再从 `Ki=0`、`Kd=0` 开始逐步增加 `Kp`，观察速度、静差和振荡。
2. 再逐步增加 `Ki` 消除静差，观察是否引入超调或振荡。
3. 最后才试 `Kd`，并结合曲线验证它对当前对象是否有帮助。每次只改一个参数。
4. 滑块范围只是本教学仿真的操作边界，不是现实设备预先已知的整定答案。

**预设参数与预期现象**（目标水位 0.6 m）

| 预设 | Kp | Ki | Kd | 现象 |
| --- | --- | --- | --- | --- |
| 默认 / P 控制 | 200 | 0 | 0 | 稳定在约 0.459 m，静差约 0.141 m |
| PI 控制 | 200 | 0.2 | 0 | 静差消失、几乎无超调，最终到达 0.6 m |
| PID 控制 | 200 | 0.2 | 20000 | 与 PI 仅差 D：实测多约 21 mm 超调 |

三个 PID 滑块统一显示 `0–100` 的控制比例，仅作为直观调参比例；内部仍分别映射到 `Kp 0–1000`、`Ki 0–5`、`Kd 0–20000`。PID 拆解中继续显示实际参数值及 `%/m`、`%/(m·s)`、`%·s/m` 单位。实际注水需要几分钟，默认用 50× 倍速观察，界面时间始终是仿真秒。

**本模型中的参数范围**（仅为仿真操作边界，不是 PID 设计结果）

| 参数 | 范围 | 依据 |
| --- | --- | --- |
| Kp | 0–1000 | 操作边界；用于观察比例作用，不代表建议值。纯 P 临界增益约 500000 是本简化模型的探索结果，不应作为现场整定目标 |
| Ki | 0–5 | 操作边界；用于观察积分消差及超调变化 |
| Kd | 0–20000 | 操作边界；放大本模型中较小的微分作用以便观察 |

本模型现象供测试后对照：纯 P 有静差；Ki 增大可消除静差但可能增加超调；本模型加大 Kd 实测反而增大超调。Kp 接近 0 且 Ki 较大时会持续振荡。

**仿真模型**：1 m × 1 m × 1 m 敞口水池，顶部进水最大 2 L/s，底部直径 20 mm 的小孔自由排水，流量系数 Cd=0.6。

```text
Qin = 0.002 × 实际阀门开度 / 100                  (m³/s)
Qout = 0.6 × π × 0.020² / 4 × √(2 × 9.81 × h)  (m³/s)
h_next = h + (Qin - Qout) / 1.0 × dt             (m)
```

0.6 m 时存水 600 L，出水约 0.647 L/s，平衡阀位约 32.4%。阀门指令纯延迟 0.3 s，一阶响应时间常数 1 s；测量微分低通时间常数 0.5 s。采用 0.05 s 固定步长、条件积分抗饱和，超出池顶的水计入累计溢流。理论静差是平衡解预测，不代表任意参数都能稳定收敛。目标滑块范围为 0–1 m；目标设为 1.0 m 时正好位于池顶，超调或进水累积可能触发溢流，因此该读数默认折叠、仅作异常指示。

该模型不包含长管阻力、泵曲线、非线性阀门特性及水面晃荡。物理参数集中在 `water-tuner.html` 的 `tankArea`、`tankHeight`、`maxInflow`、`outletDiameter` 等常量处；修改时需同步调整页面说明、预设和文档。水池容量仅由截面积乘池高确定，不能单独用容量推出目标水位。

**验证**（需 Node.js，无第三方依赖）：

```bash
node --test tests/water-model.test.cjs
```

覆盖流量、进出水平衡、P 静差、PI/PID 收敛、目标下降、空池/满池、帧率独立性、暂停重置与历史时间戳，以及 PID 分项拆解、限幅抗饱和和预设说明。

## 当前实验：调温模型（`temp-tuner.html`）

**实验目的**：用温度对象复现 P/I/D 的典型现象——纯 P 偏大超调振荡、偏小加热慢留静差，I 过大振荡加剧、合适则误差消失，D 用于微调减少超调与波动。

**预设参数与预期现象**（目标 60 °C，均为实测）

| 预设 | Kp | Ki | Kd | 现象 |
| --- | --- | --- | --- | --- |
| P 偏小 | 4 | 0 | 0 | 到 45 °C 需 634.5 s，稳态 50.0 °C，静差 10.0 °C |
| P 合适（默认） | 20 | 0 | 0 | 稳态 57.5 °C、静差 2.50 °C，加热 250 W = 散热 250 W |
| P 偏大 | 100 | 0 | 0 | 超调 0.63 °C 后来回振荡，振幅 2.08 °C、周期 92 s |
| PI 合适 | 50 | 0.3 | 0 | 静差消失、贴住目标线，超调仅 0.40 °C |
| I 过大 | 50 | 1 | 0 | 振荡加剧，振幅 2.62 °C、周期 122 s |
| PID 微调 | 70 | 0.3 | 1500 | 超调 0.00 °C；同参数去掉 D 实测超调 0.81 °C、振幅 1.83 °C |

三个 PID 滑块统一显示 `0–100` 的控制比例，内部映射到 `Kp 0–400`、`Ki 0–5`、`Kd 0–3000`。理论静差是平衡解预测：Kp=4/20 时实测与理论一致（10.00/2.50 °C），Kp=100 时系统在振荡、平衡解不再是当前误差。目标滑块 30–90 °C 均可收敛，满功率极限 95 °C。

**仿真模型**：2.0 kg 水，热容 8372 J/K，环境 20 °C、热阻 0.15 K/W，加热管最大 500 W。

```text
加热功率 = 500 × 加热管开度 / 100                    (W)
散热     = (水温 − 20) / 0.15                        (W)
水温变化 = (加热功率 − 散热) / 8372 × dt              (°C)
```

60 °C 平衡需 266.7 W（53.3%），满功率极限 20 + 500×0.15 = 95 °C，热时间常数 R×C ≈ 1255.8 s。指令延迟 20 s、加热管一阶惯性 6 s、测温传感器一阶惯性 25 s、微分低通 4 s；控制器只看测量温度（曲线中蓝实线），橙虚线为实际水温，两者之差即传感器滞后。采用 0.1 s 固定步长、条件积分抗饱和；微分作用在测量值上且在传感器更新前记录上次测量，目标突变不会产生微分冲击（实测首步 D≈0.005）。

该模型不含沸腾相变、环境温度漂移与保温层非线性。物理参数集中在 `temp-tuner.html` 的 `heatCapacity`、`thermalResistance`、`sensorTimeConstant` 等常量处；修改时需同步调整页面说明、预设和文档。

**验证**（需 Node.js，无第三方依赖）：

```bash
node --test tests/temp-model.test.cjs
```

覆盖热平衡与极限温度、纯 P 偏小（慢+静差）与偏大（超调振荡）、PI 消差与 I 过大振荡、D 抑制超调、理论静差一致性、目标阶跃恢复、传感器滞后、抗饱和与微分无冲击、预设文案、帧率独立性与历史时间戳，共 14 项；与水位实验合计 27 项（`node --test "tests/*.test.cjs"` 一次运行）。
